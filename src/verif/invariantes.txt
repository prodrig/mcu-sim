# ===========================================================================
# verif/invariantes.txt - lo que tiene que salir, exactamente
#
# Una linea por suite:
#
#     <suite>  <comprobaciones>  <tiempo simulado en ps>  [total|resto]
#
# La cuarta columna dice QUE cifra se contrasta:
#
#   total   el tiempo simulado entero, que es lo que imprime la suite.
#   resto   ese total MENOS lo que consumen T96 y T97, los dos grupos que
#           hablan con un GDB de verdad por un socket de verdad.
#
# POR QUE EXISTE. El criterio que de verdad vale en este proyecto no es que
# las suites pasen, sino que el TIEMPO SIMULADO no se mueva: si un cambio lo
# mueve, ha cambiado el comportamiento de algo aunque todas las
# comprobaciones sigan en verde. El del F407 lleva valiendo lo mismo al
# picosegundo desde la fase 7, y desde que los firmwares se versionan vale lo
# mismo en Linux y en Windows.
#
# Hasta ahora ese criterio vivia en la cabeza de quien ejecutaba las suites y
# en tres cifras repetidas por la documentacion. Aqui esta una sola vez, y
# `ci/comprueba_invariante.sh` lo lee para que la integracion continua falle
# -no avise: falle- cuando una plataforma nueva da otra cosa.
#
# COMO SE CAMBIA. Mover una de estas cifras es declarar que el comportamiento
# del modelo ha cambiado a proposito. Tiene que ir acompanado de la razon, en
# el mensaje del commit y en doc/compilacion.md 7. Si no sabes por que se ha
# movido, no la actualices: ese es exactamente el fallo que este fichero
# existe para cazar.
#
# Vease tambien verif/huellas.txt, que garantiza la otra mitad: que el
# firmware que se ejecuta es el mismo binario en todas las maquinas (T-22).
# ===========================================================================

# POR QUE EL F407 CONTRASTA `resto` Y NO `total`
#
# Porque el total de esa suite lleva dentro una cifra que NO es del modelo. El
# stub de GDB atiende su socket cada 100 us simulados (T-16), asi que mientras
# espera una respuesta de un proceso de verdad, por un TCP de verdad, el reloj
# SIMULADO avanza en pasos de 100 us. Cuantos pasos hagan falta depende de la
# maquina.
#
# Y se ha medido: el 2026-09-23, con el mismo commit y los mismos firmwares,
#
#   Linux, Windows, macOS arm64   T96+T97 = 96 665 875 ns   total 2336217899213
#   macOS Intel                   T96+T97 = 97 065 875 ns   total 2336617899213
#
# Cuatro sondeos de mas, 400 us exactos, TODOS dentro de T96+T97: la columna
# «el resto» valia lo mismo en las cuatro plataformas, al picosegundo.
#
# (Esas cifras son de antes de cerrar T-23. Al corregir el tick de mas del
#  IWDG la columna «resto» del F407 paso de 2239552024213 a 2240553274213 ps,
#  1,00125 ms mas, y el total a 2337219149213. Las otras dos suites no se
#  mueven: no ejercen el plazo del perro.)
#
# (Y la segunda vez, 2026-10-02, I-53. El arreglo del SysTick que dejaba de
#  interrumpir al reanudar tras una parada NO mueve nada: con el arreglo
#  solo, 2118 y 2240553274213 ps, al picosegundo -el F407 nunca rebasaba el
#  contador con un valor que redondeara mal-. Lo que mueve la linea es la
#  prueba nueva: T131 -5 comprobaciones- gasta 4974510342 ps propios, y
#  el resto pasa a 2245527784555. Las otras 5 comprobaciones nuevas, las del
#  aviso de I-54, van dentro de T96 y solo mueven el total.)
#
# (Y la tercera, 2026-10-03: los rebotes del pulsador. Tampoco los mueve el
#  cambio del modelo -un pulsador sin rebote no crea ningun proceso, y los
#  del banco se montan sin rebote-: sin T132, 2128 y 2245527784555 ps, al
#  picosegundo. T132 -18 comprobaciones- gasta 36300000000 ps propios, y el
#  resto pasa a 2281827784555.)
#
# O sea que contrastar el total generaba un fallo falso en una plataforma y
# tapaba el criterio de verdad. Contrastar `resto` no afloja nada: quita del
# criterio exactamente la parte que el propio proyecto tiene documentada como
# dependiente del anfitrion, y deja dentro todo lo que el modelo decide. El
# total se sigue imprimiendo, y el desglose tambien.
#
# El dia que T-16 se arregle -que el stub no gaste tiempo simulado esperando a
# un socket- esta columna vuelve a `total` y la cifra sera la de `resto`
# mas lo que T96 y T97 gasten sin esperar a nadie.
