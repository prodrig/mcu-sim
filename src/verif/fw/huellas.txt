# ===========================================================================
# verif/fw/huellas.txt - que imagen de firmware es la buena
#
# Los `.bin` de este arbol SI se versionan, y este fichero dice cuales. Cada
# linea es:
#
#     <suite>  <ruta relativa a verif/fw>  <bytes>  <FNV-1a de 32 bits>
#
# POR QUE EXISTE. Durante doce fases el tiempo simulado total del F407 valio
# `2336217899213 ps` al picosegundo, y se dio por hecho que la precondicion
# era «la misma maquina». No lo era. Los `.bin` se compilaban en cada sitio
# con el compilador cruzado que alli hubiera, y dos binarios distintos
# ejecutan un numero distinto de instrucciones: en Windows el total salia
# `2334217899213 ps`, 2 ms menos, porque `t17_coremark()` sondea el final de
# CoreMark cada 2 ms y la diferencia sale cuantizada a ese paso. Las dos
# imagenes de CoreMark no eran la misma: 14528 B frente a 14856 B. Vease
# T-22 en doc/todo.md.
#
# Versionar los `.bin` quita la causa. Este fichero es la defensa de segundo
# orden: las tres suites lo leen al arrancar y comprueban, a coste cero de
# tiempo simulado, que las imagenes que van a cargar son estas. Si alguien
# regenera un firmware -`make fw407`, por ejemplo- y le sale otra cosa, la
# suite lo dice en la primera linea en vez de dejarlo salir como una
# diferencia de picosegundos veinte grupos mas abajo.
#
# COMO SE REGENERA. Recompilar el firmware y actualizar la linea de este
# fichero es una decision, no un tramite: cambia el tiempo simulado y hay
# que actualizar tambien los invariantes de doc/compilacion.md. Este fichero
# es la UNICA fuente de verdad; ningun `.cpp` lleva una huella escrita a
# mano.
#
# CADENA CRUZADA QUE PRODUJO ESTAS IMAGENES
#   arm-none-eabi-gcc (15:13.2.rel1-2) 13.2.1 20231009   (Debian)
#   opciones: las de cada verif/fw/*/Makefile, sin tocar
#
# Se ha comprobado que NO reproducen byte a byte con otras cadenas: el
# `arm-none-eabi-gcc` 13.3.1 que trae STM32CubeIDE 1.17.0 da otro tamano y
# otra huella para el mismo fuente. Eso no es un fallo de nadie; es la razon
# por la que estos binarios se versionan en vez de recompilarse.
# ===========================================================================
